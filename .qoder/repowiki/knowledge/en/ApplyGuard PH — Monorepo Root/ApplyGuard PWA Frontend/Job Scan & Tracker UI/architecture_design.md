Three sibling React components under `src/components/` form the user-facing surface of the scanner/tracker feature:
- `ScanForm.jsx` is the landing page: it owns local state for the pasted text and optional intake fields, calls `analyzeJob` + `deriveTitle` from `../lib/analyze.js`, writes the verdict into the global store via `useApp().setResult`, then navigates to `/result/preview`. It also reads `jobs` from the store to show overdue follow-up nudges.
- `Tracker.jsx` renders the saved-jobs list. It pulls `jobs` from `useApp()`, computes aggregate stats through `trackerStats(jobs)`, and dispatches mutations (`updateJob`, `deleteJob`) plus toast notifications (`notify`). A small `JobCard` sub-component handles per-job status/follow-up/notes edits.
- `AiAssistant.jsx` is a gated panel (props-driven by the parent result view) that switches between tabs defined in `AI_FEATURES`, validates inputs, calls `callAi(activeTab, payload)` from `../lib/ai.js`, and refreshes usage via `useAuth()`.

Dependency direction is one-way: these components depend on `../store.jsx` (global state), `../auth.jsx` (tier/entitlements), and pure lib modules (`../lib/analyze.js`, `../lib/ai.js`, `../lib/stats.js`, `../lib/tone.js`, `../lib/pricing.js`, `../lib/followups.js`, `../lib/samples.js`). They never import each other; routing is done through `react-router-dom`'s `<Link>` and `useNavigate` rather than component composition.
